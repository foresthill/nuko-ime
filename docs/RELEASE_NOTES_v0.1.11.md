# ぬこIME v0.1.11 (macOS プレビュー)

v0.1.10 からの変更は **文中の学習が効かなくなる回帰の根治** が目玉です。
あわせて自己更新の完了通知と、スコア内訳を見る開発ツールが入りました。
引き続き署名 + 公証済み（Developer ID）の pre-release です。

## 目玉

### 🧠 文中の「ように / 様に」が「用に」に化ける回帰を根治

一度選び直した直後は正しく出るのに、**別の文脈の文中でまた `用に` に戻ってしまう**
（`用に` はほとんど使わないのに）という学習の回帰を直しました。

- 原因: 複数文節変換（文の大半を担う経路）で個人頻度を候補へ効かせる処理が、
  libakaza の基礎スコア（多くは負値）に頻度を**加算**していたため、
  使用回数の多い表層が負の基礎に沈み、使用回数の少ない表層に逆転されていた。
- 直し方: 既存候補も注入候補も**純粋な頻度スコアに揃える**（`max`）ことで、
  同じ読みの候補が**使用回数の順**に正しく並ぶようにした。
- 実データ（読み `ように`）での確認:
  - 修正前: `用に`(使用4回) が 1位 ❌
  - 修正後: `ように`(使用36回) が 1位 ✅ → `様に`(5回) → `用に`(4回)

> 既知の制約: 使用回数が拮抗する誤学習（例 `そこ` 27回 vs `底` 28回）は、まだ回数の多い方が
> 勝ちます。「打ち直し＝間違い側を下げる」仕組みと文脈学習は次段の課題です。

### 🔔 自己更新の「完了」を通知でお知らせ

アプリ内アップデートは完了時に本体プロセスを再起動するため、
「いつ終わったか」が分かりませんでした。更新完了時に macOS 通知
（通知センターにタイムスタンプが残る）を出すようにしました。

### 🔎 `nuko convert --explain`（開発者向け）

「なぜこの候補が1位か」を文節ごとに `スコア / 出所 / 学習回数` へ分解して表示する
CLI ツールを追加しました。誤変換を推測でなく**内訳を見て**切り分けられます。
上記の回帰もこのツールで真因を特定しました。

## 既知の制約
- **macOS のみ / arm64 単独**。変換モデル（~166MB）は手動配置（内容は v0.1.3〜と同一）。
- 使用回数が拮抗する誤学習は未対応（上記）。固有名詞・長文はまだ誤変換あり。

## インストール
手順は [`docs/MANUAL.md`](MANUAL.md) / [`docs/RELEASE.md`](RELEASE.md)。既存ユーザーは
アプリ内「🔄 アップデートを確認…」→「今すぐ更新」でも更新できます（完了時に通知）。
更新後は入力ソースを切り替える（ことえり等 → ぬこIME）と確実に反映されます。
